**明细 CSV 不要覆盖。** 每次跑用不同的文件名，老的那次留着，否则下次没法回答"这个数是从哪来的"。

## 扩容那一次发生了什么

- **dense 完全没变**（0.6250 → 0.6250）：20 道题问的全是标点组那 16 部书，Top-5 没被新增的 5,851 条挤掉。
- **bm25 反而涨了**（0.4750 → 0.5250）：字面匹配对候选池变大不敏感。
- **rrf 掉了 7.5 个点**（0.7750 → 0.7000）：两路各自没退步，退化只发生在融合环节。

## 调参：k=10 / cand=40

`rrf_k=60` 时，第 1 名和第 20 名的融合权重是 `1/61 : 1/80 ≈ 1.3` 倍，基本没有区分度。
候选池从 2,830 涨到 8,681 后，BM25 的第 1 名更可能是新语料里的干扰项，而它和真答案几乎等权。

`eval/tune_rrf.py` 在 20 道可答题上扫了 280 组配置（`rrf_k` × `candidate_k` × 两路权重）：

| 配置 | line R@5 | line MRR | 逐题变化 |
|---|---:|---:|---|
| k=60 / cand=20（原） | 0.7000 | 0.6167 | — |
| k=10 / cand=60 / BM25 权重 0.7 | 0.7500 | 0.6267 | q01、q05 命中，q15 回退 |
| **k=10 / cand=40 / 等权** | **0.7500** | **0.6183** | **只有 q01 命中，无回退** |

选了最后一个：同样是 75%，但它没有引入"权重"这个额外旋钮，而且在应用推理题上没有回退。
20 道题的样本量下，少一个待调参数比多 0.008 的 MRR 更值钱。

> **别把这个提升说成"显著"。** 20 道题里 1 道题就是 5 个百分点，
> 而且参数是在同一批题上搜出来、又在同一批题上报告的，有过拟合风险。
> 正确说法是"方向明确，但样本太小，需要扩充评测集后复验"。

## 分题型（RRF，line 口径，k=10 / cand=40）

| 题型 | n | dense | BM25 | RRF |
|---|---:|---:|---:|---:|
| 单跳释义 | 8 | 0.88 | 0.38 | 0.75 |
| 口语改写 | 4 | 0.25 | 0.50 | 0.50 |
| 应用推理 | 4 | 0.50 | 0.75 | 1.00 |
| 跨书对比 | 3 | 0.67 | 0.83 | 0.83 |
| 多跳综合 | 1 | 0.50 | 0.00 | 0.50 |

**这张表是"为什么要做 agent"的直接依据**：单跳释义题 dense 碾压 BM25（0.88 vs 0.38），
应用推理题反过来（0.50 vs 0.75）。一个全局融合权重注定只能取平均，
想让两类题都不掉分，只能让模型按题目类型自己选检索方式。

## 已修的评测 bug（2026-10-30）

`eval_matrics.py` 里的 `by_cat` 原本写在 `for mode in ("exact", "line")` 循环内部，
每道题会被记录两次（exact 一次、line 一次），所以"分题型 Recall@5（line 口径）"
实际是 **exact 和 line 的平均**。总分不受影响（`agg` 是按 mode 分开的）。

修之前，应用推理题被算成 0.88，实际是 1.00；跨书对比被算成 1.00，实际是 0.83。
**任何基于旧分题型表的结论都要重看。**

## 分词器与词典对照（2026-11-07，BM25 单路，20 道可答题）

触发问题：jieba 版 BM25 的 line recall 从 0.525 掉到 0.350，怀疑是词表太小。
用同一份语料、同一批题、只跑 BM25（不走 embedding）隔离变量：

| 配置 | hit@5 | MRR |
|---|---|---|
| 字二元组（现行默认） | **0.450** | **0.384** |
| jieba + 246 条人工词表 | 0.300 | 0.267 |
| jieba + 1,142 条篇名词典 | 0.350 | 0.339 |
| jieba_search + 1,142 条篇名词典 | 0.400 | 0.336 |
| 混合（二元组 + 篇名词典词） | 0.450 | 0.373 |

结论：

1. **词表质量确实影响 jieba**：换成从 2,830 个篇名里拆出来的 1,142 条术语后，
   普通 jieba 从 0.300 涨到 0.350，索引模式到 0.400。此前「词典无关」的说法只对
   那 246 条人工词表成立，不能推广。
2. **但最好的 jieba 仍然低于二元组**，差距来自少数题：q01（35 vs 3721）、
   q10（2 vs 257）、q09（123 vs 461）。反向 jieba 也有大胜：q07（420 vs 51）、
   q13（172 vs 73）、q20（778 vs 283）。
3. **混合分词没有增益**（0.450 / MRR 0.373）：词 token 的匹配信息是二元组的子集，
   出现「正官」这个词必然同时出现「正官」这个二元组，所以混着放只改权重、不增召回。
4. 因此保持字二元组为默认；`MINGLI_BM25_TOKENIZER` 保留 jieba / jieba_search 两个选项
   作为可复现的对照，不设为默认。

复现：`python scripts/probe_jieba_dict.py`（篇名词典）与 `MINGLI_BM25_TOKENIZER=jieba_search`。

## reranker 与分词的五组对照（2026-11-07，D1）

同一份 8,681 条语料、同一批 20 道可答题，只改分词器和重排开关。
`line` 口径，表中是 20 题均值；明细见 `eval/retrieval_*.csv`：

| 配置 | 开关 | dense R@5 / MRR | BM25 R@5 / MRR | RRF R@5 / MRR |
|---|---|---:|---:|---:|
| bigram（现行默认） | 默认 | 0.625 / 0.487 | 0.525 / 0.387 | **0.750 / 0.618** |
| jieba + 324 词典 | `MINGLI_BM25_TOKENIZER=jieba` | 0.625 / 0.487 | 0.350 / 0.300 | 0.675 / 0.513 |
| bigram + rerank | `MINGLI_RERANK=1` | **0.775 / 0.573** | 0.575 / 0.517 | 0.700 / 0.600 |
| bigram + rerank，pool=100 | 再加 `MINGLI_RERANK_POOL=100` | 0.725 / 0.557 | **0.650 / 0.567** | 0.725 / 0.564 |
| jieba + rerank | 两者都开 | **0.775 / 0.573** | 0.475 / 0.475 | **0.750 / 0.613** |

结论：

1. **重排对单路有效**：dense 从 0.625 提到 0.775，BM25 从 0.525 提到 0.575（pool=100 时到 0.650）。
2. **但对 RRF 没有增益**：三种重排配置的 RRF 最高 0.750 / MRR 0.613，没有超过 bigram 基线 0.750 / 0.618。
   两路候选被同一个 cross-encoder 重新排序后差异被压平，融合本来依赖的互补性消失。
3. 因此 reranker 保留为开关，**不设默认**；下一步应该只对融合后的候选池重排一次，而不是每路各排一次。
4. 样本仍然只有 20 题，0.025 的 RRF 差距就是半道题，不当成显著结论。

明细：`eval/retrieval_bigram.csv`、`retrieval_jieba.csv`、`retrieval_rerank.csv`、
`retrieval_rerank100.csv`、`retrieval_jieba_rerank.csv`。
