**明细 CSV 不要覆盖。** 每次跑用不同的文件名，老的那次留着，否则下次没法回答"这个数是从哪来的"。
之前的做法是每次都写到 `results_v2.csv`，语料扩容那次就把 v1 的明细盖掉了，
只能从 git 历史里捞回来（现在已恢复为 `results_v1_2830.csv`）。

## 扩容带来的变化

- **dense 完全没变**（0.6250 → 0.6250）：20 道题问的全是标点组那 16 部书，
  语义检索的 Top-5 没被新增的 5,851 条挤掉。
- **bm25 反而涨了**（0.4750 → 0.5250）：字面匹配对候选池变大不敏感，
  偶尔还能靠新语料里的同名词条多命中一条。
- **rrf 掉了 7.5 个点**（0.7750 → 0.7000）：两路各自没退步，融合之后却退了。
  说明 `rrf_k=60`、`candidate_k=20` 这组参数是在 2,830 条语料下调出来的，
  候选池变三倍后权重不再合适。**这是下一个该调的参数，不是语料的问题。**

> 结论要诚实：77.5% 是"小库里"的成绩，70.0% 才是当前真实水平。
> README 里不要继续用 77.5% 宣传。
