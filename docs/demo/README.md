用无头 Chrome 走真实接口录的，**没有 mock 模型，也没有预填回答**。

README 里嵌的是压缩过的 GIF（约 900 px / 8 fps）；这里放原始 mp4（1440×900，25 fps）和关键截图。

## 关于时间轴

两处等待做了提速，其它按实时：

- `demo-chat.mp4`：那次回答 18 秒，其中约 16 秒停在「检索古籍… 正在翻书…」，按 4 倍速压到 4 秒；
  正文逐字出现的那 4 秒接近实时。
- `demo-reading.mp4`：解读是整段返回的（不是流式），9 秒等待压到约 4 秒。

**没有跳帧、没有换答案**——看到的是真实调用的完整过程，只是等待被压缩。画面里的耗时与调用次数
是界面自己统计的。`demo-memory.mp4` 里第一轮回答只有一句话，那是模型确实按「尽量简短、先说结论」
作答的结果，不是截出来的。

## 重新录制

素材是脚本抓的，不是手点：

1. 无头 Chrome 开 `--remote-debugging-port`，用 CDP 建页、填 React 受控输入框（原生 value setter +
   `input` 事件）、点按钮、轮询 `.answer-wrap--streaming` 判断结束；
2. 流式期间按帧截 `Page.captureScreenshot`；结束后补拍其余页面；
3. `ffmpeg` 用 concat 列表把静帧和逐帧按时间轴拼成 25 fps 的 mp4，再转一版 GIF 给 README。

脚本没有进仓库（依赖本机 Chrome 路径，属于一次性素材工具）。复录时注意两点：
先 `localStorage.clear()` 换匿名 id，**然后必须真刷新一次**——只改 hash 不会重载 SPA，内存里还留着
上一个身份的会话，会得到「会话不存在」。
